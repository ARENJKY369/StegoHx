# StegoHX

**A local-first steganography operations and steganalysis suite** — hide, extract, scan, clean and evolve, wrapped in a professional security-console UI.

StegoHX is built for defenders and researchers: analyze media you are authorized to assess, build detection corpora, study how embedding parameters affect statistical detectability, and sanitize files of unknown provenance. Everything runs on your machine; nothing phones home.

## What it does

| Capability | Module | Mechanism |
|---|---|---|
| **Hide** | `image_lsb` | Keyed payload replaces the lowest 1–2 bit planes of RGB channels (sequential or seeded scatter); output re-encoded as lossless PNG |
| | `audio_lsb_wav` | Same scheme over 16-bit PCM WAV samples; RIFF container preserved |
| | `video_mp4_atom` | Payload in a dedicated top-level `stgx` atom (players skip unknown atoms; streams untouched) |
| | `text_armored` | HMAC-keystream container in PEM-style Base64 armor |
| | `network_transport` | Offline codec shaping payloads as DNS query labels or HTTP header fragments (detection training; no traffic generated) |
| **Extract** | all modules | Auto-detected module; self-describing LSB header; key required |
| **Scan** | analyzer service | Statistical ensemble: RS analysis (Fridrich's closed-form estimator), chi-square PoV attack, bit-plane coherence, quiet-segment audio statistics, ISO-BMFF container heuristics, optional ONNX model |
| **Clean** | all modules | Irreversible sanitization: zero LSB planes / strip payload atoms / strip armor |
| **Evolve** | engine + analyzer | Adaptive embedding: evaluates the strategy space, scores every candidate stego object, selects the least detectable — the red/blue-team loop for hardening detectors |
| **Report** | engine | Professional PDF per scan (OpenPDF): verdict banner, per-analyzer table, recommendations |

## Quick start

Requirements: Python 3.11+ and Node 18+ (Java 17 + Maven for the engine).

```bash
# 1) Analyzer service (statistical steganalysis)
cd ml-service
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000

# 2) Engine (stego operations, scan history, PDF reports)
cd ../backend
mvn spring-boot:run          # JDK 17; serves :8080

# 3) Console
cd ../frontend
npm install && npm run dev   # serves :3000
```

Open <http://localhost:3000>. Try the ready-made cover/stego pairs in [`samples/`](samples/) on the **Scan** page.

No Java available? The console still runs: scans are served through the analyzer fallback and clearly marked as preview mode.

```bash
# verify the analyzer on synthetic media (also refreshes samples/)
cd ml-service && .venv/bin/python scripts/selftest.py
```

| Engine PDF | [OpenPDF](https://github.com/LibrePDF/OpenPDF) 1.3.x | LibrePDF fork of iText 4 (LGPL/MPL) — clean license for report generation |
| Engine imaging | `javax.imageio` (JDK) | PNG/BMP/GIF/JPEG decode + lossless PNG encode; no native deps |
| Analyzer numerics | NumPy, Pillow | Vectorized statistics; zero-friction deployment |
| Analyzer serving | FastAPI + Uvicorn | Async multipart handling, OpenAPI docs for free |
| Console | Next.js 14 (App Router) | Typed API client, same-origin proxying, static export friendly |

## Honest limitations

- The statistical ensemble targets **LSB replacement**. LSB *matching* (±1), palette transforms and DCT-domain JPEG stego need the pluggable ONNX model path.
- Loud full-scale audio has a near-uniform low byte; embedding there is not statistically detectable by current published methods. The analyzer reports reduced sensitivity instead of pretending.
- Verdicts are probabilistic. `INCONCLUSIVE` is a first-class result and must not be treated as evidence.
